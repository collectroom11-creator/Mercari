# 빈티지샵 운영 툴 설계 (재고관리 + 가계부 통합)

작성일: 2026-10-18

## 왜 만드나

지금 샵 운영 도구가 흩어져 있다. 재고관리 앱(Electron, `inventory-app/`), 가계부(`~/Documents/가계부.html`을 브라우저로 열어서 씀), 메루카리 알림 필터(GitHub의 `config.py`를 직접 고쳐야 함), 찜 상품 할인 감시(디스코드로만 알림)가 각각 따로 있다. 재고관리 앱은 숫자가 한눈에 안 들어오고, 오래 안 팔린 상품을 챙기는 것도 사람이 기억해야 한다.

목표는 **한 앱에서 샵 운영에 필요한 걸 다 보는 것**이다. 특히 (1) 매출, 순이익, 회전율이 한눈에 보이고, (2) 할인해야 할 상품과 가격이 내려간 찜 상품을 앱이 먼저 알려주는 것.

## 목표

1. 맨 위에서 **[재고관리] / [가계부]**를 전환하는 앱 하나로 합친다.
2. 재고관리 안에 왼쪽 메뉴를 둔다: **대시보드 / 재고 입력 / 찜 목록 / 메루카리 필터**. 메뉴 맨 아래에 **🔔 알림** 버튼과 안 읽은 개수 뱃지를 둔다.
3. **대시보드:** 이번 달 매출, 이번 달 순이익, 회전율(업로드 기준), 판매중 재고원가 카드 4개와 월별 매출·순이익 막대그래프.
4. **할인 필요 알림:** 업로드 후 2주/4주/8주/16주가 지나도 안 팔린 상품을 알림 팝업에 띄우고, 단계별 할인 버튼(5%/10%/15%/20%)을 같이 둔다.
5. **찜 목록:** 기존 켄즈포스트 관심상품 자동 감시 결과를 앱에서 보여주고, 링크를 직접 추가할 수도 있게 한다. 가격이 내려가면 알림 팝업에도 뜬다.
6. **메루카리 필터 편집:** 브랜드와 가격 상한, 제외 키워드를 앱에서 고치고 저장하면 알림 봇에 반영된다.

## 하지 않을 것 (non-goals)

- 가계부와 재고 데이터를 연결하지 않는다. 판매 시점과 실제 입금 시점이 달라서, 사용자가 가계부는 따로 쓰길 원했다. 화면만 한 앱에 있고 데이터는 완전히 별개다.
- 가계부 기능은 바꾸지 않는다. 지금 화면과 기능 그대로 옮긴다.
- 후루츠 등 판매 플랫폼의 실제 가격은 바꾸지 않는다. 할인 버튼은 재고 앱의 판매가만 바꾼다.
- 순이익에 수수료나 택배비를 넣지 않는다. 수수료는 구매자 부담이고 택배비는 구매자에게 따로 받는다.
- 메루카리 필터의 제외 카테고리(악세서리/소품/시계)와 브랜드별 제외 카테고리는 화면에서 편집하지 않는다. 자주 안 바꿔서다. 기존 값은 그대로 유지한다.
- 디스코드 할인알림은 그대로 둔다. 앱 알림은 추가되는 것이지 대체가 아니다.

## 실패로 보는 것 (anti-goals)

- 가계부 기존 내역이 하나라도 사라지는 것.
- 재고 데이터(`inventory.json`)가 깨지거나 기존 기능(켄즈포스트 링크 추가, 상태 변경, 월별 정리, 일괄 할인, 일일 매입 할당량 체크)이 동작하지 않게 되는 것.
- 필터 저장이 알림 봇을 깨뜨리는 것. 예를 들어 잘못된 브랜드명이 들어가서 검색이 조용히 0건이 되는 경우.
- 앱이 사용자의 다른 로컬 작업(저장소의 커밋 안 된 변경)을 커밋하거나 덮어쓰는 것.

## 사용자가 정한 것

- 상단 탭으로 재고관리/가계부 전환. 가계부는 그대로.
- 재고관리 안에 입력 탭과 대시보드를 분리.
- 대시보드에 매출·순이익 그래프와 **업로드된 상품 기준** 회전율.
- 순이익 = **실제 판매가 − 원가**.
- 할인 알림 단계: 업로드 후 **2주 → 5%, 4주 → 10%, 8주 → 15%, 16주 → 20%** 버튼을 알림과 함께 띄운다.
- 알림은 **왼쪽 아래 알림 버튼 → 팝업**으로 본다. 맥 알림이나 미리알림이 아니다.
- 찜 목록: 켄즈포스트 관심목록 자동 읽기가 안 되면 링크를 직접 넣을 수 있게. 찜 상품이 할인되면 알림.
- 메루카리 필터: 브랜드 목록(가격 상한 수정/삭제/추가), 브랜드 추가 시 메루카리 태그명 확인, 공통 제외 키워드와 브랜드별 제외 키워드 편집, 저장하면 GitHub에 반영.
- 화면 구성은 목업(`.superpowers/brainstorm/.../layout.html`)으로 확인받았다.

## 현재 상태 (만들 때 기준점)

- `inventory-app/`: Electron 33, `main.js`(IPC), `renderer.js`, `index.html`, `style.css`, `store.js`(`~/Library/Application Support/inventory-app/inventory.json`), `pricing.js`(`computeDashboard`, `computeMonthlyBreakdown` 등), `settings.js`. 테스트: `npm test`(node --test, 현재 43개 통과).
- 이 폴더에는 **커밋 안 된 변경이 많다.** 그 위에서 작업한다.
- 상품 필드: `status`(배송전/업로드전/판매중/판매완료), `costKrw`, `listedPrice`(판매중으로 바뀐 시점의 판매가), `listPrice`(현재 판매가), `listedAt`, `soldAt`, `actualPrice`(실제 판매가).
- 기존 일괄 할인(`applyBulkDiscount`)은 현재가에 할인을 곱한다(복리). 할인 뱃지는 `listedPrice` 대비 %로 표시한다.
- 찜 감시: `wishlist-watch.js`를 launchd(`com.collectroom.wishlist-watch`)가 30분마다 실행한다. 켄즈포스트 관심상품 페이지를 읽고, 메루카리 현재가를 확인해서 내려가면 디스코드 웹훅으로 보낸다. 상태 파일은 `wishlist-watch.json`(`items[id] = {title, lastPrice, soldOut, checkedAt}`)이다.
- 일일 매입 할당량: `daily-quota.js`와 launchd(`com.collectroom.daily-quota`), 미리알림 연동. 건드리지 않는다.
- 가계부: 단일 HTML 파일(약 83KB, 스타일 내장). `window.storage`가 있으면 그걸 쓰고 없으면 `localStorage`를 쓴다. 키는 `ledger:transactions`, `ledger:recentDesc`, `ledger:categories`, `ledger:categoryKeywords`, `ledger:seed_jan_jun_2026`이다. 사용자는 파일을 더블클릭해서 브라우저로 연다. 데이터는 그 브라우저의 localStorage에 있다.
- 메루카리 봇: 저장소 루트의 `config.py`(브랜드 49개 전부 30,000엔, 제외 키워드 등), `main.py`, GitHub Actions에서 1분마다 실행된다. 브랜드명은 `facets/brands.json`의 이름과 정확히 맞아야 매칭된다. 원격 `main`에는 봇이 1분마다 커밋하므로 push는 항상 rebase 후 재시도가 필요하다.

## 동작 상세

### 상단 탭과 가계부
- 상단 바에 [재고관리] [가계부]를 둔다. 가계부는 `가계부.html`을 앱 안으로 가져와서 그대로 띄운다.
- 가계부 저장소: 가계부 코드가 이미 지원하는 `window.storage` 인터페이스(`get(key)` → `{value}` 또는 키가 없으면 에러, `set(key, value)`)를 앱이 제공해서, 데이터를 앱 데이터 폴더의 JSON 파일(예: `ledger.json`)에 저장한다. (설계자 판단: 재고 데이터와 같은 폴더에 있어야 백업이 쉽다.)
- **기존 데이터 옮기기 (한 번만):** 원본 `~/Documents/가계부.html`에 임시 "백업 내보내기" 버튼을 추가해서, 사용자가 평소 쓰던 브라우저로 열고 한 번 누르면 위 5개 키를 JSON 파일로 내려받게 한다. 새 앱의 가계부에 "백업 불러오기"로 그 파일을 넣는다. 옮긴 뒤 거래 건수가 원본과 같은지 확인해서 보여준다. 원본 파일과 브라우저 데이터는 지우지 않는다. (설계자 판단: 사용자가 어느 브라우저를 쓰는지 몰라도 되고, 브라우저 내부 저장 파일을 직접 파싱하는 것보다 안전하다.)

### 대시보드
- 카드 4개 (기준: 이번 달, 한국 시간)
  - **이번 달 매출:** 이번 달 `soldAt`인 상품의 `actualPrice` 합.
  - **이번 달 순이익:** 같은 상품들의 `actualPrice − costKrw` 합.
  - **회전율 (업로드 기준):** 이번 달 판매된 상품 원가 ÷ (이번 달 판매된 상품 원가 + 지금 판매중 상품 원가). 배송전/업로드전 상품은 넣지 않는다.
  - **판매중 재고원가:** 판매중 상품의 `costKrw` 합.
- 월별 막대그래프: 월별 매출과 순이익(판매월 기준). 데이터가 있는 첫 달부터 이번 달까지.
- 기존 `computeDashboard`/`computeMonthlyBreakdown`과 겹치는 계산이 있으면 재사용하거나 확장한다.

### 할인 필요 알림
- 대상: `status === "판매중"`이고 `listedAt`이 있는 상품.
- 단계: 업로드 후 경과일 ≥ 14 → 5%, ≥ 28 → 10%, ≥ 56 → 15%, ≥ 112 → 20%. 지금 해당하는 **가장 높은 단계**만 보여준다.
- 할인 기준가는 **처음 업로드 가격(`listedPrice`)**이다. 버튼을 누르면 `listPrice = round(listedPrice × (1 − 단계%))`로 바꾼다. 할인이 복리로 겹치지 않는다. (설계자 판단: 기존 할인 뱃지가 `listedPrice` 기준이라 맞췄다. 사용자에게도 이렇게 설명했다.)
- 이미 그 단계 이상으로 할인돼 있으면(`listPrice ≤ listedPrice × (1 − 단계%)`) 알림에서 빠진다. 따로 상태를 저장하지 않는다.
- 사용자가 할인하지 않고 넘기고 싶을 때를 위해 항목별 "숨기기"를 둔다. 숨긴 건 다음 단계가 되면 다시 뜬다. (설계자 판단)
- 기존 수동 일괄 할인 버튼(5/10/20%)은 그대로 둔다.

### 찜 목록
- 찜 목록 탭: `wishlist-watch.json`의 상품을 보여준다(제목, 현재가, 처음 가격 대비 변화, 품절 여부, 메루카리/켄즈포스트 링크).
- 링크 직접 추가: 켄즈포스트 링크나 메루카리 링크를 넣으면 감시 목록에 들어간다. 켄즈포스트 목록을 다시 읽어도 직접 넣은 항목은 유지된다. 삭제도 가능하다.
- 가격 인하 알림: `wishlist-watch.js`가 가격 인하를 발견하면(지금 디스코드로 보내는 시점) 앱이 읽을 수 있게 인하 기록(상품, 이전가, 새 가격, 시각)도 남긴다. 알림 팝업은 확인하지 않은 인하 기록을 보여준다. 디스코드 전송은 그대로 둔다.
- 감시 주기는 기존 launchd 30분을 그대로 쓴다.

### 알림 팝업
- 왼쪽 메뉴 맨 아래 🔔 버튼과 개수 뱃지. 개수는 할인 필요 상품 + 확인 안 한 찜 가격 인하.
- 팝업 섹션: "할인 필요"(상품명, 업로드 N주째, 현재가, 단계 버튼, 숨기기)와 "찜 상품 가격 인하"(상품명, 이전가 → 새 가격, 보기 링크, 확인).

### 메루카리 필터
- 지금 `config.py` 안에 파이썬 코드로 박혀 있는 편집 대상 값(브랜드 목록, 브랜드별 가격 상한, 공통 제외 키워드, 브랜드별 제외 키워드)을 저장소 루트의 JSON 파일(예: `filters.json`)로 옮기고, `config.py`는 그 파일을 읽어서 같은 변수 이름으로 내보낸다. 앱은 JSON만 고친다. (설계자 판단: 파이썬 코드를 텍스트로 고치는 것보다 안전하다.) `main.py` 동작은 바뀌면 안 된다. 옮기기 전후로 `main.py`가 보는 값이 같은지 확인한다.
- 화면: 브랜드 표(이름, 가격 상한, 삭제), 브랜드 추가(이름 + 상한, 기본 30,000엔), 공통 제외 키워드, 브랜드별 제외 키워드.
- 브랜드 추가할 때 `facets/brands.json`에서 이름을 찾는다. 정확히 일치하면 통과, 아니면 비슷한 후보를 보여주고 고르게 한다. 맞는 게 없으면 저장할 수 없다.
- 저장: 로컬 저장소(`~/Documents/fashionstudy`)에서 `filters.json`만 커밋하고 `git pull --rebase --autostash` 후 push한다(최대 몇 번 재시도). 성공/실패를 화면에 보여준다. 다른 파일은 절대 커밋하지 않는다.
- 저장 전에 원격 최신 `filters.json`을 받아서 편집 중 충돌이 없게 한다.

## 설계 검토 후 정한 세부사항 (설계자 판단)

- **가계부 불러오기는 덮어쓰기:** 새 앱의 가계부는 처음 열면 예시 데이터(1~6월 시드)를 만들 수 있다. "백업 불러오기"는 5개 키를 백업 파일 값으로 **전부 교체**한다. 시드 플래그 키도 포함해서, 불러온 뒤 예시 데이터가 다시 생기지 않게 한다.
- **직접 추가한 찜 링크는 별도 파일:** 앱과 감시 스크립트가 같은 파일을 동시에 쓰지 않도록, 직접 추가한 링크는 `wishlist-manual.json`에 저장하고 `wishlist-watch.js`가 매 실행마다 읽어서 감시 목록에 합친다. 가격 인하 기록도 별도 파일(예: `wishlist-drops.json`)에 감시 스크립트가 추가하고, 앱은 "확인" 상태만 따로 저장한다.
- **데이터 누락 처리:** 지금 데이터에는 판매완료인데 `actualPrice`/`soldAt`이 없거나, 판매중인데 `listedPrice`/`listedAt`이 없는 상품이 없다(2026-10-18 확인). 앞으로 생기면 대시보드 합계와 할인 알림에서 그 상품만 빼고, 조용히 0으로 계산하지 않는다.
- **필터 저장 커밋:** 커밋 메시지는 "Update Mercari filters (app)"이고 `filters.json` 한 파일만 담는다. push는 사용자의 기존 git 인증(터미널에서 쓰는 것과 같은 것)을 그대로 쓴다.

## 설계자에게 맡기는 것

- 화면의 세부 스타일. 목업과 기존 `style.css` 톤을 따른다.

# 재고 관리 앱 설계

## 목적
개인 리셀 사업의 매입/재고/판매를 추적해서 "이번 달 실제 순이익"을 명확히 보여준다.
브랜딩·팬층이 아니라 월 100만원 순이익 달성 여부 판단이 유일한 목표.

## 형태
`desktop-app/`(알림·마진계산기 트레이 앱)과는 별개인 독립 Electron 앱.
새 디렉터리: `inventory-app/`

## 로그인 (켄즈포스트 세션)
- 서버가 비밀번호를 저장하거나 대신 입력하지 않는다.
- 첫 실행 시 "로그인" 창에 `https://kenzpost.com` 로그인 페이지를 그대로 로드.
- Electron의 `persist:kenzpost` 세션 파티션을 사용해 로그인 쿠키를 로컬에 영구 저장.
- 이후 상품 링크 조회는 이 세션(쿠키)으로 인증된 요청을 보낸다.
- 세션 만료(파싱 실패 시 로그인 페이지가 다시 뜨는 것으로 감지) 시 로그인 창을 다시 띄운다.

## 등록 흐름
1. 사용자가 상품 링크(`kenzpost.com/mercari/bid.s/...` 등)를 입력창에 붙여넣고 "가져오기" 클릭.
2. 앱이 저장된 세션으로 해당 페이지를 로드해 상품명·엔화가격을 파싱.
3. 원가 계산:
   - `원가(원) = 엔화가격 × 환율(100엔 기준, 페이지에 표시된 값) / 100 × (1 + 예상관세율)`
   - 예상관세율 기본값 23% (지금까지 관측된 22~24% 평균), 설정에서 조정 가능.
4. 최소판매가 = 원가 / 0.6 (판매가 기준 마진율 40%, `(판매가-원가)/판매가 = 0.4`)
5. 화면에 원가/최소판매가 표시, 사용자가 실제 목표 판매가를 입력.
6. "재고로 등록" 클릭 시 아래 데이터 모델로 저장 (상태: `재고`).

## 데이터 모델 (SQLite, 로컬 파일 `inventory.db`)

```
items
  id            INTEGER PRIMARY KEY
  title         TEXT        -- 파싱된 상품명 (수정 가능)
  source_url    TEXT
  jpy_price     INTEGER
  fx_rate       REAL        -- 등록 시점 환율(100엔 기준)
  duty_rate     REAL        -- 적용한 예상관세율
  cost_krw      INTEGER     -- 계산된 원가(원)
  target_price  INTEGER     -- 목표 판매가
  actual_price  INTEGER     -- 실제 판매가 (판매완료 시 입력)
  status        TEXT        -- '재고' | '판매완료' | '개인구매'
  created_at    TEXT
  sold_at       TEXT
  memo          TEXT
```

## 화면 구성
1. **등록 화면**: 링크 입력 → 가져오기 → 원가/최소판매가 미리보기 → 목표판매가 입력 → 저장
2. **재고 목록**: 상태별 필터(재고/판매완료/개인구매), 각 항목 클릭 시 상태 전환 + 실제 판매가·판매일 입력
3. **대시보드**:
   - 재고 총원가 합계 vs 상한선(설정값, 기본 300만원) — 진행률 바
   - 이번 달 매출원가 = 월초재고 + 이번달매입 − 월말재고 (자동 계산, 월초/월말 재고는 그 시점 '재고' 상태 항목의 원가 합)
   - 이번 달 순이익 = 이번 달 '판매완료' 항목의 실제 판매가 합계 − 이번 달 매출원가
   - 목표(100만원) 대비 진행률

## 범위 밖 (이번 버전에서 제외)
- 클라우드 동기화, 여러 기기 간 공유
- 소모품비·배송비·구독료 등 고정비의 자동 집계 (수동으로 대시보드 목표치에 감안)
- 켄즈 외 다른 구매대행 사이트(재팬잉/헤이재팬) 자동 연동 — 추후 필요시 추가
